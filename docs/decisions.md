# Design decisions

- 2026-10-31: `Bridge::on_tx_done` returns `Option<BusEvent>` so internal allocation polls do not fabricate host/local TX events; the chosen address emits `LaAllocated`, and the physical-address announcement links to it.
- 2026-10-31 (D1/M3): A directed transmission ending after a NACKed block is complete once high past `DATA_TOTAL.max` from the ACK fall, even without EOM. Publish the received blocks as `Frame { ack: false }`, not a timing error, preserving absence evidence.
- 2026-10-31 (D2/M1/M2): Silently drop idle data-width pulses; suppress repeat errors until a valid start pulse. Keep edge-order timestamps independent of `poll`. Executor order is read now, drain GPIO edges, poll, then TX completion, preventing false out-of-order errors and late echoes.
- 2026-10-31 (D3/M4): Add `Decoder::set_transmitting(bool)`; never ACK our own sends and never synthesize sampled ACK from membership. Rebuild allocation ACK membership from the selected LA plus configured extras, excluding the candidate while polling. The fixed LA (first type candidate for auto) is the implicit own entry, not an extra, removing the stale default `[0]`.
- 2026-10-31 (D4/M5): Add one-shot `TxAction::Abort` after mid-block arbitration/line failure so the executor cancels RMT and releases the line immediately.
- 2026-10-31 (D5/M6/m9): RMT is TX-only; receive edges and follower ACK triggers require a timestamping GPIO ISR. `SendBlock` includes ACK trailing high; queue the next block immediately after positive ACK, with explicit `block_start_us` equal to the previous end so relative samples stay correct for queued transactions. `AckDue::fall_at_us` is only a prediction; actual fall triggers ACK.
- 2026-10-31 (D6/M7/m5): Replace `Tx::step(now, bus_busy)` with `step(now, quiet_since_us)` and expose `Decoder::quiet_since_us(now)`. Busy/low returns now; otherwise use last edge, extended to ACK fall + BIT at frame completion. Recheck every step; foreign activity uses NEW instead of SAME/RETRY; bookkeeping retains only the two-second give-up clock.
- 2026-10-31 (D7/M8): Public `Bridge::next_seq()` allocates from the one wrapping per-boot counter for rejected/busy, line, and overrun events emitted by the executor.
- 2026-10-31 (D8/M9, revised with lead approval): Lenient `RawTxRequest` owns bounded `String<32>` id and `String<64>` data, with u64 numeric fields; borrowed strings cannot support escaped JSON without allocation. Validation returns `Submission` or `(Option<RequestId>, Reason)`. Ingress overflow, wrong types and malformed JSON become uncorrelated `malformed` rejection. Omit unavailable ids (not null); rejected destination/data are optional when invalid/overlong. Remove impossible bounded-length `SubmitError` variants; retain destination validation because `Frame` fields are public. Retries clamp to MAX_ATTEMPTS - 1.
- 2026-10-31 (D9/M10): Separate frame-level `RxError::LineLow` (`err kind:line_low`) from stateful bus health at `timing::STUCK_LOW = 100_000`. Add `RxEvent::Line` and `BusEvent::Line` with stuck/recovery transitions; proto maps to `line bus:stuck_low|ok`.
- 2026-10-31 (D10/m1/m2): Count NACKs independently from arbitration/line failures; retry while nacks <= retries and attempts < MAX_ATTEMPTS. Final attempt wins for status, correcting contradictory all-attempt wording.
- 2026-10-31 (D11/m3): Samples over `timing::SAMPLE_SLACK = 200` µs late are line errors, including never-delivered samples, avoiding infinite past-deadline waits.
- 2026-10-31 (D12/m4/m10): `TxAction::Done { outcome, final_attempt_start_us }` authoritatively timestamps `Bridge::on_tx_done(outcome, start_us)`. Remove the decoder-echo timestamp override; match echoes only to suppress local replies. Wait final ACK completion (past decoder timeout for NACK) and drain RX before TX publication.
- 2026-10-31 (D13/m6/m7/m8, Luna 1/2): String visitors accept escaped JSON; manual bus decoding bounds addresses to 15; unknown kind/status values remain errors, while unknown keys are ignored. `serde_json` is optional under std and a dev-dependency. Name `OtaRequest` and `StateRequest` in the API contract (rename the former `StateCommand`).
- 2026-10-31 (Luna 3/4): Acceptance explicitly covers ACK sampling at SAMPLE_AT and line-error retries with retries=0. ACK pulse timing accepts the combined low range because initiator/follower share the line; its sampled polarity, including a rise exactly at SAMPLE_AT, is independent of ack-set membership.
- 2026-10-31 (phase 2 B1/M1/m7): Firmware builds in-tree with Cargo-relative absolute SDK defaults so the 8000-byte stack cannot silently revert. Commit a 4-MB dual-OTA partition layout and IDF rollback bootloader before the first USB flash; erase all old flash once to remove Tasmota credentials/layout. Box Bridge to reduce main-stack pressure.
- 2026-10-31 (phase 2 B2/m4): Start and retain the buffered UART console before fallible startup. Invalid stored cfg/secrets fall back with scrubbed static codes; retry NVS once after erasing on NO_FREE_PAGES/NEW_VERSION_FOUND; Wi-Fi setup/connect errors are nonfatal. Other fatal errors retain show/factory-reset/reboot recovery. WPA parser and stored-secret validation share exact passphrase rules.
- 2026-10-31 (phase 2 m1): Remove SNTP. TLS checks trust chain and hostname but deliberately not validity dates (HAVE_TIME_DATE unset), avoiding an NTP availability dependency on the LAN.
- 2026-10-31 (phase 2 m2/m3): Correct protocol §2 to esp-mqtt's drop-newest semantics. Count enqueue failures and enabled deleted-message callbacks, report accumulated overrun after enqueue recovery using Bridge's sequence, reconnect after failed subscribe. Keep connection state/generation and pending shutdown PUBACK atomic; only bounded data enters the 32-slot callback channel.
- 2026-10-31 (phase 2 m5): MQTT reset restores default CEC config but preserves provisioned node (and secrets/system boot), avoiding topic/ACL loss; console factory-reset erases the entire default NVS partition, including node, secrets and boot.
- 2026-10-31 (phase 2 m6): Request an eight-character git abbreviation and compile-time assert the complete FW string fits 24 bytes, moving any version/hash overflow from boot-time panic to build failure.
- 2026-10-31 (phase 2 m7): Mark the running app valid on main after MQTT connects or after 60 s without a broker, also in recovery mode. This is a documented phase-2 provisioning exception to §9's future pending-OTA MQTT/status deadline, not an implemented OTA downloader.
- 2026-10-31 (phase 2 Luna High/Medium/Low): Online Status.bus serializes null when unmeasured (its Rust type was already Option<BusState>); phase 2 must not claim ok without sampling. Keep measured enum states and minimal offline LWT unchanged. Queue.max means capacity 16; test deferred bus counters individually and real snapshot telemetry separately. Protocol status now lists implemented/deferred sections.
- 2026-10-31 (phase 2 m7 build): ESP-IDF resolves custom partition CSV paths relative to esp-idf-sys's generated CMake project, not firmware/. Use esp-idf-sys's supported ESP_IDF_GLOB_* file staging with a Cargo-relative absolute base to copy and track partitions.csv in OUT_DIR; keep the portable filename in sdkconfig.defaults.
- 2026-10-31 (bench): `CONFIG_ESP_MAIN_TASK_STACK_SIZE` raised 8000 → 32768. First boot on hardware overflowed the main task stack before the console started (crash loop `A stack overflow in task main`); the main task hosts NVS/Wi-Fi/MQTT setup, serde_json and the boxed `Bridge`. Measured headroom is a phase-3 item.
- 2026-10-31 (bench): the lab firewall port-group `mqtt` (IoT clients → broker) gained 8883 next to 1883; TLS from the bridge was silently dropped before. Lab-side change, recorded here because the TLS-default decision depends on it.
- 2026-10-31 (phase 2b): Replace the obsolete pull-OTA API (`OtaRequest`, `Command::Ota`, `Verb::Ota`) with push HTTP OTA and Receiving progress. Add Healthz/HttpError/OtaAccepted; reuse LogLine and OtaProgress, with no compatibility shims. This is the approved protocol §9/§11 cutover.
- 2026-10-31 (phase 2b HTTP): Main remains the sole command/config/Bridge owner. A bounded mailbox routes HTTP through the MQTT command planner and common executor; read-only HTTP snapshots avoid locking the bus owner. Tokens are generated with esp_fill_random, persisted before activation, compared with a full-token XOR, and printed only by explicit serial show token.
- 2026-10-31 (phase 2b SSE): Use IDF async request copies with one bounded 16-event mailbox per client and at most three 4096-byte-stack writer tasks. esp-idf-svc's normal handler completes its response on return, so a native exact SSE handler is necessary. This keeps both httpd and main responsive; overflow disconnects only the slow client. MQTT publication is the shared fan-out point, with 15-second keep-alives.
- 2026-10-31 (phase 2b OTA): Stream and hash at most 4096 bytes at once with sha2 (default features off), check actual inactive-slot size, digest and ESP-IDF project `aether`, persist pending id plus target partition before complete, then return 202 and reboot after 500 ms. Partition identity, rather than firmware version, reliably distinguishes rollback even for same-version development images.
- 2026-10-31 (phase 2b health): Supersede phase-2 unconditional MQTT-connect confirmation for pending OTA: require online status PUBACK; without it reset at 60 seconds so CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE rejects PENDING_VERIFY on the next boot. Keep the provisioning-only 60-second fallback. Publish confirmed/rolled_back before clearing the durable pending record.
- 2026-10-31 (phase 2b UI/log): Embedded vanilla UI uses authenticated fetch SSE and browser-local token storage. Prefer WebCrypto SHA-256, with an inline local implementation because plaintext LAN HTTP is not a secure context. Wrap EspLogger and retain 64 scrubbed application-only info/warn/error records; dependency diagnostics and console token printing never enter the log ring.
- 2026-10-31 (phase 2b B1, superseding phase-2 m7 and phase-2b health provisioning fallback): Bootloader PENDING_VERIFY is authoritative, queried in Health::new before fallible startup. NVS only supplies the id and detects rolled_back when the recorded slot differs on a nonpending image. Rename BootKind::Provisioning to Valid and delete ConfirmProvisioning; blank otadata is initialized VALID by the bootloader, so no non-OTA confirmation is needed. Clear same-slot stale records without re-arming rollback; confirmation/report retries never revert an already valid image to pending.
- 2026-10-31 (phase 2b B2): Store the HTTP token separately in secrets/token and exclude it from the secrets/json credentials blob. Generate or replace only that key; never save credentials from load fallback. A failed/stricter credential read must not destroy shared NVS credentials and strand both OTA slots.
- 2026-10-31 (phase 2b M1): Bracket first-token esp_fill_random with bootloader_random_enable/disable before Wi-Fi/ADC startup, supplying hardware entropy even on an unprovisioned board.
- 2026-10-31 (phase 2b M2): Delete http_shutdown. Main always reboots after two seconds or earlier on offline PUBACK; the handler's post-response reboot flag is only a speed-up. HTTP timeout/disconnect cannot disable the deadline or strand a board in offline/shutdown state.
- 2026-10-31 (phase 2b Opus minor 1/2): Refuse OTA while the running image is PENDING_VERIFY with 409 busy before incrementing the id counter. Document that a second streaming upload waits in the single httpd task's accept backlog; 409 covers an accepted upload awaiting reboot, not concurrent streaming.
- 2026-10-31 (phase 2b Opus minor 3/4): Refresh HTTP status snapshots at most once per second instead of every 10-ms loop. Arm an esp_timer one-shot in Health::new that resets a still-pending image at 60 s independently of main, and reset immediately if the timer cannot be armed; successful bootloader confirmation cancels it.
- 2026-10-31 (phase 2b Luna Medium/Low 1/2): Mark protocol §9/§11 implemented and fix the overview to push-OTA. Both normal and native SSE handlers call the tested authorized route policy; pure UploadProgress drives the real handler's receiving/verifying/rebooting/failed payloads and deduplicates percentages. Extend host regressions for auth exemptions, bootloader-vs-record authority, shutdown deadlines and upload success/failure progress; NVS/bootloader/timer effects still need bench verification.
- 2026-10-31 (bench, toolchain): with esp Rust 1.97.0.0 / esp-clang 21.1.3 a function taking six by-value parameters (`&str`, `&Config`, `Status` by value, `u32`, `Storage`, `Arc<Hub>`) received the last argument as uninitialised stack (0xa5a5a5a5 fill) on Xtensa — confirmed by printing `Arc::as_ptr` on both sides of the call. Workaround: `http::Http::new(http::Init { .. })` takes one by-reference struct. Rule until the toolchain is fixed: firmware functions take at most a few register-sized arguments; bundle larger argument lists into a struct passed by value or reference.
- 2026-10-31 (bench): console thread stack 6 KiB → 12 KiB and SSE worker 4 KiB → 8 KiB after an intermittent LoadProhibited in the console channel's waker mutex (10/11 boots crashed on one build, 0/10 after). `CONFIG_ESP_TASK_WDT_PANIC=y` and comprehensive heap poisoning are enabled for the bench phase; poisoning cost is accepted until phase 3 timing work says otherwise.
- 2026-10-31 (bench, verified): OTA upgrade over `POST /api/ota` (1.47 MB in 14 s, `202 {"id":"o-1"}`, reboot into the other slot, confirmed after MQTT) and forced rollback (image that never connects: 60 s timer restart → bootloader falls back → old image publishes `rolled_back`) both behave as protocol §9 specifies.
- 2026-10-31 (bench fixes 1/3, superseding phase-2b UI/log forwarding): `events::Logger` writes scrubbed application records directly to Rust stdout, including microsecond timestamp, level and module target, and keeps the independent 64-entry ring. IDF filters match exact tags: enabling `aether` did not enable `aether::ffi`/`aether::config`, so forwarding to `EspLogger` silently suppressed module output. All IDF/dependency tags now remain disabled; application filtering still allows only the `aether` root/modules at info/warn/error. Add static lifecycle codes for IP-ready Wi-Fi, MQTT connect/disconnect, OTA accepted/verified/failed/confirmed/rolled_back, successful config application, restart/reset requests and pending-image confirmation. MQTT callbacks only set atomic flags; main logs connection transitions, keeping blocking UART/ring operations out of the callback. No new pure logic was introduced, so no wiring-only host tests were added.
- 2026-10-31 (bench fix 2, hardware verification required): UART0 now has a 1024-byte TX ring alongside its 512-byte RX ring, rather than entering IDF's synchronous zero-TX-buffer path for every VFS character. Before worker startup/backend switching, drain Rust stdout and newlib stdout/stderr once, then leave the C streams unbuffered so later C stdio flushes have no previous line buffer to replay. Installed IDF v5.4.2 `uart_vfs.c` writes one character via `uart_write_bytes` and returns the original VFS write size; `uart.c::uart_tx_all` advances its pointer and returns the original byte count in both TX modes. Rust stdout uses descriptor writes, not newlib `FILE` buffering. The generated SDK configuration already selects `CONFIG_ESP_CONSOLE_UART=y`, UART0, 115200 baud. These code paths do not establish a deterministic fragment-replay cause: buffering/backend interaction is a hypothesis, not a proven diagnosis. The TX-ring/C-stdio handoff change is the best-guess mitigation for the lead to verify on serial hardware, including early/ROM-log tails and explicit prompt flushes; it does not claim to fix arbitrary memory corruption.
- 2026-10-31 (bench fix 4): Audited all firmware-owned free functions and methods, including by-value `Status`, `Init`, `Arc`, `Modem`, `EspSystemEventLoop`, HTTP `Request`, enums/options/results and the boot-health callback. Convert five-parameter `apply_plan` to one `ApplyPlan` context; convert `MqttLink::publish` and `MqttLink::json` (five including `self`) to one borrowed-payload `Publication` argument plus `self`, migrating every firmware caller. Existing `Http::new(Init)` is already bundled; fix its inaccurate by-reference comment (the struct is passed by value). Remaining functions/methods have at most four parameters; external ESP-IDF C calls and host crates retain their contracts. No public Rust API in `docs/design.md` or MQTT wire signature changed. The AGENTS invariant now records the Xtensa-only workaround.
